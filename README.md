# presale-market

청약홈의 새 아파트 분양·무순위 공고를 매일 모아, 공고문 조건(전매제한, 거주의무, 해당·기타지역, 계약금, 중도금 이자)과 주택형별 분양가 대비 주변 시세를 계산해 `02_data/latest.json`으로 내는 저장소다. 공공데이터만 쓴다. 누가 신청할 수 있는지, 얼마가 남는지는 계산하지 않는다. 그 판정은 이 파일을 읽는 쪽이 각자의 조건으로 한다.

## 돌아가는 방식

- `.github/workflows/collect.yml`이 매일 05:17(한국 시간) 최근 14일 공고를 모아 `02_data/latest.json`을 커밋한다. 손으로 돌릴 때 `names`에 단지명을 넣으면 지난 공고를 찾아 `02_data/check.json`을 만든다.
- 공고문 PDF에서 읽은 조건은 `02_data/notices/`에 공고마다 남겨 다시 받지 않는다.
- 신고 기한이 지난 달의 실거래는 Actions 캐시(`cache/`)에 두고 다시 받지 않는다.

## 시세 계산

방법은 백테스트가 고른다. `03_notes/backtest/result.json`의 `adopted`가 채택한 방법과 그 오차(지난 공고 오차의 중간값 `MdAPE`, 80% 분위 `P80`)이고, 매일 모으기가 그 방법으로 시세를 내고 오차를 `latest.json`의 `market_error`에 싣는다. 판정 규칙과 회차별 결과는 `03_notes/backtest/README.md`, 방식 설계는 `03_notes/v2-설계.md`에 있다.

- 지금은 v2c다(2026-11-03 3회차 채택). 시세는 「이 단지 분양권이 공고 뒤 6 ~ 18개월에 거래될 값」의 예상이고, 분양가 × e^(a + b × x)다. x는 v1 주변 시세 ÷ 분양가의 로그(−0.5 ~ 0.3에서 자름)이고, 주변 시세가 없으면 분양가 × e^a0이다. 3회차 계수는 a 0.0287, b 0.098, a0 0.0131이고 영남 2023 ~ 2025 공고로 맞췄다(`01_code/fit_v2c.py`). 충청·호남·강원·대전·세종·광주 2023 ~ 2025 공고 98건에서 오차 중간 2.5%, 80%가 4.0% 안이었다. 같은 단지 거래가 있으면(조합원 취소분·무순위) v1을 쓴다.
- 자동 점검: 사람이 계수를 다시 맞추지 않아도 되도록, 「시세 계산 백테스트」 워크플로가 반년마다(매달 20일에 깨어 마지막 점검이 170일 넘었을 때) 3회차와 같은 절차를 최근 공고로 되풀이한다. 받는 날에서 585일 앞까지 30개월의 영남 공고로 계수를 다시 맞추고, 같은 창의 검증 묶음 공고에서 지금 계수와 새 계수, v0, v1을 견준다. 그다음 `backtest.py` 머리의 규칙대로 방법과 계수, 오차(`P80`)를 `result.json`에 고쳐 적는다. 지금 쓰는 계수와 맞춘 창은 `latest.json`의 `market_method`와 `market_error`(`coef`, `fit_window`, 점검일 `checked`)에 나온다. 정답 공고가 30건 미만이거나 지표 대조가 실패하면 아무것도 바꾸지 않는다. 그러면 `checked`가 오래되고, 받는 쪽은 이것을 보고 경고할 수 있다.
- 지난 공고에서 새 단지 분양권은 분양가와 거의 같은 값에 거래됐고, 주변 단지 시세(v1)는 분양가보다 낮게(중간 −20%) 나왔다. 주변 시세가 분양가보다 높고 낮은 정도는 실제 웃돈을 조금만 설명한다(기울기 0.098).
- v1(주변 시세, `cmp.v1`에 같이 싣는다): 같은 단지 → 같은 읍·면·동 분양권 → 같은 읍·면·동 5년 이내 단지 → 같은 시·군·구 분양권 → 같은 시·군·구 5년 이내 단지 순으로 3건 이상 있는 범위의 최근 10건 ㎡당 중간값에 전용면적을 곱한다.
- 맞지 않을 수 있는 곳: 계수를 맞춘 공고는 공고 뒤 18개월 안에 분양권 거래가 3건 넘은 단지다. 전매제한이 길어 그 사이 분양권을 팔 수 없는 단지(수도권 분양가상한제 등)는 표본에 없어, 그런 공고의 웃돈은 이 식이 낮게 볼 수 있다.

## 직접 돌리기

```bash
export DATA_GO_KR_KEY=...   # 공공데이터포털 일반 인증키
python 01_code/presale.py collect
python -m unittest discover -s 01_code
```

공고문을 읽으려면 `pdftotext`(poppler-utils, poppler-data)가 있어야 한다.

## `latest.json`

| 칸 | 내용 |
|---|---|
| `schema` | 2(2026-11-03부터 `market_error`, `cmp.method`·`range`가 있다) |
| `today`, `lookback_days`, `market_method` | 기준일, 모은 기간, 시세 계산 방식 |
| `market_error` | 채택한 시세 방법의 백테스트 오차(`method`, `MdAPE`, `P80`, `N`)와 점검일 `checked`, 판정 창 `window`, v2c·v0이면 계수 `coef`(없으면 3회차 계수)와 맞춘 창 `fit_window`. 읽는 쪽은 시세 × (1 − `P80`)을 보수적인 시세로 쓸 수 있다 |
| `notices[].detail`, `models` | 청약홈 공고 상세와 주택형 목록(원래 칸 이름 그대로) |
| `notices[].sido`, `sigungu`, `umd`, `closed`, `rent` | 공급 위치, 접수 마감 여부, 임대 공고 여부 |
| `notices[].notice` | 공고문에서 읽은 조건. 못 읽은 칸은 `null`이고 전매제한만 법령 표 값(`resale_fallback_months`)을 따로 준다 |
| `notices[].types[]` | 주택형별 분양가(`price`, 만원), 시세 비교(`cmp`), 전세 추정(`jeonse`) |
| `cmp` | `method`(v1·v2c), `market`(시세, 만원), `range`(v2c는 지난 오차의 20·80% 분위로 낸 범위, v1은 근거 거래 ㎡당 25·75%), `per`(㎡당), `gain`·`rate`(분양가 대비), `scope`, `trend`(이전 6개월 대비 흐름). v2c는 `gap`(주변 시세 ÷ 분양가 로그)과 같은 주택형의 v1 값 `v1`, v1은 근거 거래 `trades`와 단지별 묶음 `comps` |
| `errors` | 조회에 실패한 공고 |
